# Implementation audit

The original Windows server run used the existing `NeuroEZCModel`, `NeuralDynamicsResidualEncoder`, `WindowGraphSpectralEncoder`, `ChannelTemporalEncoder`, `CrossSeizureMILAggregator` and `PatientChannelClassifier`. The source module SHA-256 values are recorded in `PROTOCOL_LOCK.json`; the additional `physics_dynamics.py` SHA-256 is `566fa4786262fd409f64e22eccf747af59d8cd0e58b7f21cec8f3464eb27ec8a`. The current feature-cache SHA-256 and fixed-partition SHA-256 matched the lock on the server. The published runner rejects changed source modules; this assertion was added while R0 was underway and applied to the R1 resume process, not to R0's already-running process. No source module was modified during training.

The separately inspected split/cache-loader source hashes are `data_factory.py` = `1f0a219c8315841c3ef4cb5d6c122d1d1b9d97b9cc853faa6efced824ff398c0` and `ez_dataset.py` = `2ebb25896ece9144813892b5ce09cfb4883c2f04dfb7cccafea327a0f49fb580`. These two supplementary hashes were documented after the run; they were not included in the original protocol-lock source guard.

The source cache contains 90 patients before the fixed-manifest allow-list. The active experiment has exactly 80 patients, 256 seizure records and 7,635 canonical channels. Every fold uses the existing disjoint fit/validation/test roles; the validation stage builds fit and validation datasets only. Each validation fold has 13 patients. The patient-index label source is EZ-positive, converted by the existing loader into the model's NEZ-positive training target; the patient-relative classifier remains enabled. Center IDs are present as bookkeeping metadata but the default single-expert forward path does not use them as predictive input.

R0 and R1 use the same nine-variable four-view B0 representation and identical training/selection settings. The R0 shared initial state is copied into every shape-matched R1 parameter before training, so the common base, temporal and classifier weights begin identically. R1 alone enables the 6-D HLV branch. The experiment-local view adapter reorders the source `zdelta,delta` output into the locked per-variable `delta,zdelta` order; values and fit-only normalization are otherwise unchanged. Gate weights initialize to zero and bias to -4.0; all auxiliary losses are zero. The selected checkpoint maximizes validation patient Macro-F1 after validation-only threshold selection on the fixed 0.05–0.95 grid; no outer scores participate.

An evaluation-only mask-shape bug was encountered after R1 fold 1 completed training. The selected checkpoint was preserved. The diagnostic mask was fixed by adding its embedding-axis singleton dimension; fold 1's already-selected checkpoint was reloaded and evaluated without retraining. This repair changes no features, model, optimizer, split, loss, checkpoint or threshold. The other four folds completed normally. Both variants have 5/5 validation summaries and no nonfinite results.

`VALIDATION_GATE.json` is the frozen six-condition decision record. It is `pass=false`. No current-run outer-test evaluation or HLV-shuffle ablation was performed; the server-side outer output directory does not exist. Only aggregate fold-level outputs are published here. Private checkpoints, patient/channel predictions, caches and runtime logs remain on the server and are not uploaded.

The released code replaces the executed script's four absolute source/cache/manifest/runtime path constants with environment variables of the same meaning. This is a path-only sanitization for publication; no model, data membership, training, selection, metric or gate code changed. The local code patch also records the diagnostic mask repair and checkpoint-resume behavior actually used for R1 folds 1–5.
