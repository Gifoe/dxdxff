## Recorded engineering failures and repairs

1. An initial server `python -m pytest test_model.py` subprocess terminated
   natively in NumPy BLAS initialization before test collection. The same three
   tests had passed locally. PowerShell stdin did not terminate subsequent
   commands after its `throw`, so the formal trainer launched. Its complete
   actual-FIT CUDA admission passed before formal optimization. Unchanged
   server tests subsequently passed3/3 with NumPy imported before pytest/Torch.
   This order discrepancy is disclosed, not relabeled as a fully successful
   initial preflight. No scientific source/backend/precision was changed.
2. The supplementary support/evaluation entry point initially resolved a
   generic `train` import to a historical dependency directory, raising
   `ImportError` before a support checkpoint or support-input freeze existed.
   The old entry-point bytes were retained privately and are available in Git
   revision2499b40. The corrected entries load this experiment's unchanged
   `train.py` explicitly by path. Import admission passed. Main80 checkpoints,
   features and selections did not change.
3. The supplementary trainer reused the main trainer's public progress field.
   `restore_status.py` reconstructs the main completion field from all80
   hash-verified frozen checkpoints, validation files and public epoch history.
   This corrects an administrative progress overwrite, not model state.
4. The first PowerShell stage wrapper observed a null process exit-code field
   although all five support-completion artifacts existed. The wrapper now
   retains the process handle and requires the exact stage-completion evidence
   in addition to a nonzero-exit check. No support fit was repeated.
5. Local SSH stdout silence timeouts and UTF8/Windows-codepage stderr decoding
   errors were observed. They are not diagnosed as invalid credentials or
   server disconnection. The final foreground wrapper emits ASCII keepalives,
   keeps the SSH owner alive, preserves distinct log names and takes an
   exclusive coordinator lock. No unrelated job, driver or global setting was
   modified. Runtime logs and original failure evidence remain private.
